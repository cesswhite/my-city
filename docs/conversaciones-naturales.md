# Conversations consistent with a neighbor's life

The runtime label `Conversando con…` (talking with…) indicates that a character is reserved for a conversation. It does not explain what they were doing before the greeting. Each encounter retains a brief snapshot of that previous scene: physical task, current place, destination, routine, and next plan. Context distinguishes work in progress, rest, and travel. Personal goals and occupation are not evidence that a task is underway or already finished.

The same distinction applies to manual chat and autonomous conversations between neighbors. Each participant receives their own scene. The clock or a new destination can update a pending route without rewriting what they were doing when the encounter started. This state is temporary and discarded at the end, without creating artificial memories every frame.

Responses address the question's intent. Asked “What were you up to?”, a neighbor who was organizing tools can say “I was organizing the workshop tools.” They do not answer “Talking with you,” turn a goal into a hobby, or turn casual conversation into a quest. Follow-up questions build on the last statement. Greetings, farewells, and “Fine, thanks” receive everyday conversational replies.

Initial options are based on visible actions without revealing biographies that have not yet been shared. Subsequent buttons follow the topic and avoid asking answered questions again; if the neighbor said where to buy oil, they do not ask where to get it again. Choosing an intention through a button sends a sentence; it does not move the character, grant objects, or complete errands.

There is still one request per response, with streaming and the 12,000-character context limit. Isolated tests inspect the actual request body using a transport without network access, both autonomous participants, rest at home, walking destinations, drafts, and memories. Provider evaluation uses test characters and does not access the user's save.
